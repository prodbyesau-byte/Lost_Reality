# HUD, pause and save management

Normal gameplay has no permanent game title, location, level or XP block. The underlying level, XP and location services remain intact. GameHUD now displays `E - <action>` at the bottom-right using the existing Interactable.prompt() and PlayerInteractor focus signal. Range, line-of-sight and input handling remain owned by PlayerInteractor. The prompt disappears immediately on lost focus, pause or scene transitions; it never follows the player.

SaveLoadMenu hosts the existing character/savepoint views and a simplified ESC pause view. Only RESUME, SETTINGS and QUIT GAME appear in pause. Escape resumes from pause and returns from Settings to pause. SettingsContent is shared with the main menu and refreshes actual setting values on entry. Quit requires confirmation. Loading and deletion are available from the main menu; savepoints retain their existing save/load workflow with deletion added.

SaveDeleteDialog is shared by both save-management views. It captures the exact slot and a revision covering primary, .bak, .tmp and .bak.tmp artifacts. Cancel performs no IO. Confirmation delegates through SaveManager's busy/transition guard to SaveStore; a changed or empty revision is rejected. Deletion targets only the four exact paths from the validated slot ID, removing recovery files before the primary. Metadata lives inside those files. IO failures are reported; partial cleanup can leave the primary/recovery state available for review and retry. No unrelated files or slots are enumerated/deleted. Autosave can be deleted and subsequent autosaves still work.

No save schema or migration changes, placeholders or new gameplay systems. Tests use isolated temporary stores, including cancellation, changed-save protection, all artifact cleanup, invalid/corrupt saves, other-slot preservation, autosave deletion/recreation, immediate menu refresh, pause/settings/quit flow and existing savepoint interaction. The complete regression suite remains required.
